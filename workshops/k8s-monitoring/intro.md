# Kubernetes Monitoring with Loki

One of the primary use cases for Loki is to collect and store logs from your Kubernetes cluster. These logs fall into three categories:

1. **Pod logs**: Logs generated by containers otherwise known as logs running in your cluster.

1. **Kubernetes Events**: Logs generated by the Kubernetes API server.

1. **Node logs**: Logs generated by the nodes in your cluster.

In this tutorial, we will deploy Loki and the K8s Monitoring Helm chart to collect two of these log types: Pod logs and Kubernetes events. We will also deploy Grafana to visualize these logs.

## Things to know

Before you begin, here are some things you should know:

- **Loki**: Loki can run in a single binary mode or as a distributed system. In this tutorial, we will deploy Loki as a single binary otherwise known as monolithic mode. Loki can be vertically scaled in this mode depending on the amount of logs you are collecting. There will be a particular point where you will need to switch to a distributed mode for large scale production use cases.

- **Deployment**: We will deploy Loki, Grafana and Alloy (As part of the Kubernetes Monitoring Helm) in the `meta`{{copy}} namespace of your Kubernetes cluster. Make sure you have the necessary permissions to create resources in this namespace. These pods will also require resources to run, so make sure you have enough resources available in your cluster. It also possible to just deploy the Kubernetes monitoring helm within your cluster and write logs to an external Loki instance or Grafana Cloud.

- **Storage**: Loki requires a storage backend to store logs. In this tutorial, we will use the default storage backend provided by Loki (MinIO). It is recommended to migrate to a more production-ready storage backend like S3, GCS, or Azure Blob Storage for production use cases.

## Prerequisites

Before you begin, you will need the following:

- A Kubernetes cluster running version `1.23`{{copy}} or later.

- [kubectl](https://kubernetes.io/docs/tasks/tools/) installed on your local machine.

- [helm](https://helm.sh/docs/intro/install/) installed on your local machine.
